## Part 1 — What Attributes Are

So far we've used:

```
<tagname>Content</tagname>
```

Attributes live inside the **opening tag**.

Structure:

```
<tagname attribute="value">Content</tagname>
```

Example:

```
<html lang="en">
```

Here:

- `lang` is the attribute
- `"en"` is the value

Attributes give extra information about an element.

Without attributes, tags are basic.

With attributes, tags become meaningful.

---

### Concept Anchor — Think of Attributes Like Details on a Form

If a tag is a person's name:

Attributes are their:

- address
- phone number
- job title

The name alone isn't enough.

The details give context.

---

### Why This Matters

Modern websites rely heavily on attributes for:

- navigation
- accessibility
- styling
- interaction

Ignoring attributes limits what HTML can do.

---

### Micro Recap

You should now understand:

- where attributes live
- what they do
- why they exist

---

### Quoted Values (Important Rule)

Attribute values must always be wrapped in quotes.

Correct:

```
<a href="about.html">
```

Incorrect:

```
<a href=about.html>
```

Browsers may accept it — but don't rely on that.

**Professional HTML always uses quotes.**

## Part 2 — Core Attributes

These are the two you'll use constantly.

### `class`

`class` groups elements for styling and targeting.

Example:

```
<p class="subtitle">Full-Stack Developer</p>
```

Right now nothing changes visually.

Later, CSS will use this label.

Think of `class` as a sticky note you attach for later styling.

---

### Common Beginner Mistake

Using random class names like:

```
<p class="p1">
```

Good class names describe purpose, not order.

`subtitle` is meaningful.
`p1` is not.

---

### `id`

`id` uniquely identifies **one** element.

Example:

```
<h1 id="hero-title">John Doe</h1>
```

Rules:

- each `id` must be unique
- never reuse the same one

IDs are often used for:

- page navigation
- JavaScript targeting
- anchor links

---

### Friction Moment — "Why Not Just Use Class Everywhere?"

Because sometimes you need one specific element.

- `class` = many
- `id` = one

This distinction matters later.

---

### Micro Recap

You now know:

- `class` groups things
- `id` identifies one thing

## Part 3 — Link Attributes (`href`)

Meet the anchor tag:

```
<a>Link</a>
```

On its own, it does nothing.

It becomes useful with `href`.

Example:

```
<a href="#contact">Contact Me</a>
```

`href` tells the browser where to go.

It can link to:

- another page
- a section on the same page
- an external website

Example:

```
<a href="https://github.com">My GitHub</a>
```

---

### Common Beginner Mistake

Writing:

```
<a>Contact</a>
```

This looks like a link but isn't clickable.

No `href` = no navigation.

---

### Why This Matters

Links are what connect the web.

Without `href`, your site is isolated.

---

### Micro Recap

A real link always needs:

- `<a>`
- `href`

## Part 4 — Image Attributes (`src`, `alt`)

Images use the `<img>` tag.

It is a **void element**.

Basic structure:

```
<img src="image.jpg" alt="Description">
```

### `src` — Where the Image Lives

`src` means **source**.

Example:

```
<img src="assets/profile.jpg" alt="Portrait of John Doe">
```

If the path is wrong, the image won't show.

This is one of the most common beginner frustrations.

---

### Friction Moment — The Broken Image Icon

If you see a little broken image symbol:

It means the browser couldn't find the file.

Check:

- folder name
- file spelling
- extension

**HTML is strict about paths.**

---

### `alt` — Why It's Not Optional

`alt` describes the image.

It is used by:

- screen readers
- search engines
- fallback when image fails

Good:

```
alt="Portrait of John Doe smiling"
```

Bad:

```
alt="image"
```

Always describe what matters in the photo.

---

### Why This Matters

Accessibility is not optional.

Professional developers write good `alt` text.

---

### Micro Recap

Every image should have:

- a valid `src`
- a meaningful `alt`

---

## Why Attributes Exist

Attributes allow HTML to:

- connect pages
- identify elements
- describe content
- prepare for styling
- support accessibility

Without them, HTML would be flat and limited.

**Attributes give structure relationships and purpose.**

---

## Project Milestone — Add Link + Image to Hero

Upgrade your Hero section like this:

```
<body>
  <h1 id="hero-title">John Doe</h1>
  <p class="subtitle">Full-Stack Developer</p>
  <p>I build clean, modern, and user-focused web experiences.</p>

  <a href="#contact">Contact Me</a>

  <img src="assets/profile.jpg" alt="Portrait of John Doe">
</body>

```

Save.

Refresh.

If the image doesn't appear:

- confirm the file is inside `assets/`
- check spelling exactly

---

### Real Developer Scenario

In real projects, broken images usually mean wrong paths.

Not "HTML is broken."

Developers always check file structure first.
