## Part 1 — Natural Flow of a Web Page

Browsers follow a simple rule:

**Elements render from top to bottom.**

This is called **normal document flow**.

Without CSS:

- Block elements stack vertically
- Inline elements flow inside text

HTML has layout behavior even before CSS exists.

**Understanding this is critical.**

---

### Concept Anchor — Think of It Like Writing on Paper

Imagine writing in a notebook.

You write one sentence.

Then the next line goes below it.

That's block flow.

Now imagine bolding a word inside a sentence.

The word changes —

but the sentence continues.

That's inline flow.

The browser behaves like paper before styling is added.

---

### Why This Matters

When layouts break later, it's almost always because:

- normal flow was misunderstood
- block and inline behavior was ignored

Professional developers understand default behavior first.

**Then they change it intentionally.**

---

### Micro Recap

You should now understand:

- browsers render from top to bottom
- layout exists even without CSS
- flow is predictable

## Part 2 — Block Elements

A block element:

- Starts on a new line
- Takes full available width
- Pushes the next element below it

Examples you already used:

- `<h1>`
- `<p>`

Look at this:

```html
<h1>John Doe</h1>
<p>Full-Stack Developer</p>
<p>I build modern websites.</p>

```

They stack vertically.

Even if the text is short, each element owns its own row.

**That is block behavior.**

---

### Friction Moment — "But It's Not Full Width Visually"

It **is** full width.

It just doesn't look dramatic yet because:

- there's no background color
- there's no border

Later, when we add CSS, you'll see the box clearly.

For now, trust the model.

---

### Experiment

Add:

```
<p>Paragraph One</p>
<p>Paragraph Two</p>

```

Refresh.

They stack automatically.

No CSS.

Just block behavior doing its job.

---

### Micro Recap

Block elements:

- stack vertically
- create structural sections
- behave like boxes

---

## Part 3 — Inline Elements

Inline elements behave differently.

They:

- Do NOT start on a new line
- Only take as much width as they need
- Live inside block elements

Example:

```html
<p>I am a <strong>developer</strong>.</p>
```

`<strong>` does not break the line.

It stays inside the paragraph.

Other inline elements:

- `<a>`
- `<span>`
- `<em>`
- `<strong>`

Inline elements modify content.

Block elements structure content.

---

### Real Example From Chapter 2

This link:

```html
<a href="#contact">Contact Me</a>
```

When sitting alone under paragraphs, it appears on its own line.

But that's because it's surrounded by block elements.

Technically, `<a>` is inline.

Place it inside text:

```html
<p>Want to work together? <a href="#contact">Contact Me</a></p>
```

Now it flows naturally inside the sentence.

**That is inline behavior.**

---

### Common Beginner Mistake

Thinking:

**"If it's on a new line, it must be block."**

Not always.

Context matters.

Flow depends on surrounding elements.

---

### Micro Recap

Inline elements:

- live inside blocks
- do not break lines
- modify text

## Part 4 — `<div>` vs `<span>`

Now we introduce two containers.

They have no visual meaning by default.

They are **grouping tools**.

### `<div>` — Block Container

`<div>` is block-level.

It:

- starts on a new line
- takes full width
- groups larger sections

Example:

```html
<div>
  <h1>John Doe</h1>
  <p>Full-Stack Developer</p>
</div>

```

Visually, nothing changes.

Structurally, everything changes.

Now those elements belong together.

---

### Why Grouping Matters

Without grouping:

- CSS selectors become messy
- layout adjustments affect unintended elements
- sections bleed into each other

With grouping:

- structure becomes intentional
- styling becomes clean
- sections have boundaries

**This is how real layouts begin.**

---

### `<span>` — Inline Container

`<span>` is inline.

It:

- does not create a new line
- wraps small pieces of text

Example:

```html
<p>I am a <span>Full-Stack Developer</span>.</p>
```

Use `<span>` when targeting small pieces inside sentences.

---

### Concept Anchor — Big Box vs Highlighter

Think of:

- `<div>` as a cardboard box that holds items
- `<span>` as a highlighter around a word

One groups sections.

The other marks small details.

---

### Micro Recap

Use:

- `<div>` for large grouping
- `<span>` for small inline grouping

## Part 5 — Apply This to the Portfolio

Right now, your Hero elements are floating independently.

**Let's group them.**

Update your `<body>`:

```html
<body>
  <div>
    <h1 id="hero-title">John Doe</h1>
    <p class="subtitle">Full-Stack Developer</p>
    <p>I build clean, modern, and user-focused web experiences.</p>

    <p>
      Want to work together?
      <a href="#contact">Contact Me</a>
    </p>

    <img src="assets/profile.jpg" alt="Portrait of John Doe">
  </div>
</body>

```

Save.

Refresh.

Visually, not much changed.

**Structurally, everything changed.**

You now have a Hero container.

---

### Real Developer Scenario

In real projects, designers often say:

**"Wrap that whole section so we can style it."**

If you didn't group your content, that request becomes painful.

**Grouping early prevents chaos later.**

---

### Why This Matters

You are no longer just writing tags.

You are designing structure.

Structure first.

Style later.

Behavior after that.

**That order prevents technical debt.**
