# Part 1 — Natural Flow of a Web Page

Browsers follow a simple rule:

**Elements render from top to bottom.**

This is called **normal document flow**.

Without CSS:

- Block elements stack vertically.
- Inline elements flow inside text.

HTML has layout behavior even before CSS exists.

**Understanding this is critical.**

---

# Part 2 — Block Elements

A block element:

- Starts on a new line
- Takes the full available width
- Pushes the next element below it

Examples you already used:

- `<h1>`
- `<p>`

Look at this:

```
<h1>John Doe</h1>
<p>Full-Stack Developer</p>
<p>I build modern websites.</p>
```

They stack vertically.

Even if the text is short, each element takes its own line.

**That is block behavior.**

You can think of block elements as stacked boxes.

### Experiment

Add this under your content:

```
<p>Paragraph One</p>
<p>Paragraph Two</p>
```

Refresh.

They stack automatically.

No CSS.

Just natural block behavior.

# Part 3 — Inline Elements

Inline elements behave differently.

They:

- Do NOT start on a new line
- Only take as much width as they need
- Live inside block elements

Example:

```
<p>I am a <strong>developer</strong>.</p>
```

`<strong>` does not break the line.

It stays inside the paragraph.

Other inline elements:

- `<a>`
- `<span>`
- `<em>`
- `<strong>`

Inline elements modify content.

Block elements structure content.

### Real Example From Chapter 2

This link:

```
<a href="#contact">Contact Me</a>
```

If it sits alone, it appears on its own line because it follows block elements.

But technically, `<a>` is inline.

If placed inside a paragraph:

```
<p>Want to work together? <a href="#contact">Contact Me</a></p>
```

Now it flows inside the sentence.

**That is inline behavior.**

# Part 4 — `<div>` vs `<span>`

Now we introduce two structural containers.

They have no semantic meaning.

They are **grouping tools**.

### `<div>` — Block Container

`<div>` is block-level.

It:

- starts on a new line
- takes full width
- groups larger sections

Example:

```
<div>
  <h1>John Doe</h1>
  <p>Full-Stack Developer</p>
</div>
```

Visually, nothing changes.

Structurally, everything changes.

Now the heading and paragraph are part of one group.

### `<span>` — Inline Container

`<span>` is inline.

It:

- does not create a new line
- wraps small pieces of text

Example:

```
<p>I am a <span>Full-Stack Developer</span>.</p>
```

It is used when styling small pieces of text later.

### When to Use Which?

Use `<div>` for:

- Sections
- Layout grouping
- Large structural blocks

Use `<span>` for:

- Small inline text styling
- Words inside sentences

# Part 5 — Apply This to the Portfolio

Right now, your Hero elements are separate.

**We will group them properly.**

Update your `<body>` to:

```
<body>
  <div>
    <h1 id="hero-title">John Doe</h1>
    <p class="subtitle">Full-Stack Developer</p>
    <p>I build clean, modern, and user-focused web experiences.</p>

    <p>
      Want to work together?
      <a href="#contact">Contact Me</a>
    </p>

    <img src="assets/profile.jpg" alt="Portrait of John Doe">
  </div>
</body>
```

Save.

Refresh your browser.

Visually, not much changed.

Structurally, you now have a **Hero container**.

This container will later become a semantic `<header>` or `<section>`.

For now, we are learning structure before semantics.

### Why This Matters

Without grouping:

- Styling becomes messy
- Sections blend together
- Layout becomes unpredictable

With grouping:

- Each section has boundaries
- Future CSS becomes clean
- Architecture becomes intentional

**You are starting to think like a front-end developer.**
