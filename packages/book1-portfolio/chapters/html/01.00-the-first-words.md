## Part 1 — What HTML Actually Is

HTML stands for **HyperText Markup Language**.

Important:

HTML is not a programming language.

It does not:

- calculate
- loop
- make decisions

HTML describes structure.

It tells the browser:

- this is a heading
- this is a paragraph
- this is navigation
- this is the main content

Think of HTML as the skeleton of a website.

CSS will later control appearance.

JavaScript will later control behavior.

Right now, we build structure.

---

### Concept Anchor — Think Like Building a House

If a website were a house:

- HTML is the walls, doors, and rooms
- CSS is the paint and decoration
- JavaScript is the electricity and smart devices

Trying to style or animate before structure is like painting air.

First, you build the house.

---

### Why This Matters

Many beginners rush straight into styling.

They copy fancy templates without understanding structure.

Later, everything breaks.

Strong HTML makes:

- layouts easier
- accessibility better
- SEO stronger
- CSS simpler

Professional developers never skip this step.

- HTML describes structure
- It is not logic
- It is the foundation of every webpage

## Part 2 — Tag Anatomy

Everything in HTML is built using **tags**.

Most tags follow this structure:

```html
<tagname>Content</tagname>
```

Example:

```html
<p>Hello world</p>
```

- `<p>` is the opening tag
- `</p>` is the closing tag
- The text in between is the content

The slash `/` means closing.

---

### Friction Moment — The Silent Page Problem

A very common beginner mistake is forgetting to close a tag.

When that happens:

- the browser tries to guess
- sometimes it works
- sometimes the layout breaks strangely

You might see:

- text in the wrong place
- styles not applying
- sections swallowing each other

The browser is being polite — but guessing.

We don't rely on guessing.

---

### Common Beginner Mistake

```html
<p>Hello world
```

No closing tag.

Always close what you open (unless it's a void element).

---

### Void Elements (Self-Closing Elements)

Some tags don't wrap content.

Example:

```html
<meta charset="UTF-8">
```

There is no closing `</meta>`.

Other common ones:

- `<img>` for images
- `<br>` for line breaks
- `<link>` for CSS files

These are called **void elements**.

---

### Nesting (Parent and Child)

Tags can live inside other tags.

Example:

```html
<body>
  <h1>John Doe</h1>
</body>

```

- `<body>` is the parent.
- `<h1>` is the child.

Indentation doesn't affect the browser.

It affects humans.

Clean structure makes code readable and debuggable.

---

### Why This Matters

Messy HTML becomes impossible to style properly.

When your structure is clean:

- CSS becomes easier
- bugs become obvious
- teamwork becomes smoother

Good developers respect structure.

---

### Micro Recap

You should now understand:

- how tags open and close
- what void elements are
- how nesting works

## Part 3 — The Boilerplate (The Real Page Foundation)

Every proper HTML page begins with a standard structure.

Open your `index.html`.

Replace everything with:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>John Doe — Developer Portfolio</title>
  </head>

  <body>
  </body>
</html>

```

Save the file.

Now let's understand it.

---

### `<!doctype html>`

This tells the browser:

**"This is modern HTML5."**

Without it, browsers can enter something called **quirks mode**.

Quirks mode causes:

- broken layouts
- strange spacing
- inconsistent behavior

Always include it.

---

### `<html lang="en">`

This wraps the entire page.

`lang="en"` tells:

- screen readers
- search engines

what language the page uses.

Accessibility starts here.

---

### Friction Moment — "But It Works Without It"

Yes — sometimes pages still load without doctype or lang.

But professional pages don't rely on "sometimes."

Web development is about predictability.

---

### Micro Recap

Your page now has:

- a proper HTML foundation
- modern standards enabled

## Part 4 — `<head>` vs `<body>`

This separation is critical.

### `<head>`

The head contains **invisible** information.

Things like:

- encoding rules
- page title
- metadata
- CSS links (later)

Nothing in `<head>` appears visually on the page.

### `<body>`

The body contains everything the user sees:

- headings
- text
- images
- links
- sections

If you see it on screen, it lives in `<body>`.

---

### `<meta charset="UTF-8">`

This sets character encoding.

Without it:

- emojis may break
- special characters may glitch

Always include it.

---

### `<title>`

The title shows in:

- browser tabs
- search results
- bookmarks

It does NOT appear inside the page itself.

Try changing it and refreshing.

Instant feedback.

---

### Why This Matters

SEO, accessibility, and professionalism all start here.

Many beginner sites ignore `<head>` completely.

Real-world apps don't.

---

### Micro Recap

You should now understand:

- what lives in `<head>`
- what lives in `<body>`
- why both matter

## Part 5 — Headings & Paragraphs

Now we create real visible content.

Inside your `<body>`, add:

```html
<body>
  <h1>John Doe</h1>
  <p>Full-Stack Developer</p>
  <p>I build clean, modern, and user-focused web experiences.</p>
</body>

```

Save.

Refresh.

You just built your first real section.

---

### Friction Moment — "Why Doesn't Enter Create Space?"

In HTML, pressing Enter does nothing visually.

Spacing comes from tags — not from the keyboard.

Structure always beats typing.

---

### Understanding Headings

HTML has headings from `<h1>` to `<h6>`.

Rules:

- One `<h1>` per page
- They define structure, not size
- Don't choose based on appearance

Your `<h1>` is the main topic of the page.

---

### Understanding Paragraphs

Paragraphs wrap blocks of text.

They automatically add spacing.

This is how readable content is created.

---

### Common Beginner Mistake

Using headings just to make text big.

Later, accessibility breaks.

Search engines get confused.

Always use tags by meaning.
